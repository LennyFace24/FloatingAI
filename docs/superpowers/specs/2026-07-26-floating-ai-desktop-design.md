# Windows 悬浮 AI 对话助手设计规格

日期：2026-07-26
状态：已通过用户审阅

## 1. 产品定位

这是一个 Windows 桌面端轻量 AI 对话应用。应用常驻画面顶层，默认表现为一个可拖拽的悬浮球。用户遇到问题时点击悬浮球，即可打开小型对话窗口，与 AI 进行实时文本对话。

核心定位不是复刻完整在线 AI Chat 网站，而是提供一个低打扰、快速唤起、快速收起的桌面助手。

第一版目标：让用户无需打开浏览器、无需切换到大型网页应用，就能在当前工作流里完成一次轻量 AI 问答。

## 2. 平台与技术方向

### 2.1 目标平台

第一版只面向 Windows 桌面。

不在第一版支持 macOS、Linux、Android 或 iOS。跨平台能力可以作为后续技术选择的保留空间，但不能影响第一版的 Windows 悬浮体验。

### 2.2 推荐技术栈

推荐采用 Tauri + Rust + Web UI。

- Rust/Tauri 负责桌面能力：窗口创建、置顶、拖拽、托盘、快捷键、本地配置、安全存储、AI 请求代理。
- Web UI 负责界面：悬浮球、对话面板、消息流、输入框、设置页、流式渲染。
- 前端框架可选择 React、Vue 或 Svelte。若没有既有代码约束，推荐 React 或 Svelte。React 生态成熟，Svelte 更轻量。

### 2.3 备选技术

Electron + React：开发速度快，生态成熟，但包体和内存占用较高，不符合“轻量替代在线 Chat 网站”的核心定位。

.NET/WPF 或 WinUI 3：Windows 原生能力强，但 UI 迭代和未来跨平台弹性弱。若团队已有 .NET 经验，可重新评估。

当前推荐：Tauri。它在轻量化、桌面能力和 Web UI 迭代效率之间最平衡。

## 3. MVP 范围

### 3.1 第一版必须包含

1. 顶层悬浮球
   - 应用启动后显示一个小型悬浮球。
   - 悬浮球可拖拽。
   - 悬浮球保持置顶。
   - 悬浮球位置在本地持久化。

2. 对话窗口
   - 点击悬浮球展开对话窗口。
   - 对话窗口保持置顶。
   - 打开后输入框自动聚焦。
   - 支持按 Esc 收起回悬浮球状态。
   - 支持点击收起按钮回到悬浮球状态。

3. 文本 AI 对话
   - 支持用户输入文本问题。
   - 支持多轮上下文对话。
   - 支持流式输出 AI 回复。
   - 支持停止当前生成。
   - 支持复制 AI 回复。
   - 支持清空当前会话。

4. AI 服务配置
   - 支持配置 API Key。
   - 支持配置 Base URL。
   - 支持配置模型名。
   - 第一版按 OpenAI-compatible Chat Completions 流式接口实现；后续如需支持 Responses API，应通过 AI Provider Adapter 扩展，不影响 UI 层。

5. 系统集成
   - 支持系统托盘。
   - 托盘菜单包含显示/隐藏、设置、退出。
   - 支持全局快捷键唤起或收起窗口。
   - 支持开机自启开关。

6. 本地持久化
   - 保存窗口位置。
   - 保存基础设置。
   - 保存当前会话状态。第一版不要求完整历史会话库。

### 3.2 第一版不包含

以下能力不进入 MVP：

- 截图提问。
- 语音输入。
- 文件上传。
- 插件系统。
- 账号系统。
- 云同步。
- 团队协作。
- Prompt 市场。
- 长期历史搜索。
- 自动读取屏幕内容。

这些功能会显著扩大权限、隐私、性能和交互复杂度，应在轻量文本体验稳定后再规划。

## 4. 交互模型

### 4.1 状态

应用有四个主要 UI 状态：

1. FloatingBall
   - 默认状态。
   - 只显示悬浮球。
   - 低干扰，占用极小屏幕面积。

2. ChatPanel
   - 用户点击悬浮球或按快捷键后进入。
   - 显示对话内容和输入框。
   - 输入框自动聚焦。

3. SettingsPanel
   - 从对话窗口或托盘进入。
   - 用于配置 AI 服务、快捷键、开机自启。

4. Hidden
   - 用户通过托盘或快捷键隐藏所有窗口。
   - 应用仍在后台运行。
   - 可通过托盘或快捷键恢复。

### 4.2 状态转换

- FloatingBall -> ChatPanel：点击悬浮球，或按全局快捷键。
- ChatPanel -> FloatingBall：按 Esc，点击收起按钮，或发送完成后由用户手动收起。
- FloatingBall/ChatPanel -> SettingsPanel：点击设置入口或托盘设置菜单。
- 任意可见状态 -> Hidden：托盘隐藏或快捷键隐藏。
- Hidden -> FloatingBall 或 ChatPanel：托盘显示或快捷键唤起。

默认快捷键建议为 Alt + Space，但必须允许用户修改。若与系统或其他应用冲突，设置页应提示用户重新绑定。

## 5. 界面结构

### 5.1 悬浮球

悬浮球应保持克制，不像广告悬浮窗。

建议规格：

- 直径 44-56 px。
- 可拖拽。
- 鼠标悬停时轻微放大或提升阴影。
- 显示一个简洁 AI 图标或应用标识。
- 请求处理中可显示轻量加载状态。
- 不显示大段文字。

### 5.2 对话窗口

对话窗口是主要工作面，不做完整网页聊天布局。

建议结构：

- 顶部栏：应用标识、当前模型状态、设置按钮、收起按钮。
- 消息区：用户消息、AI 消息、流式输出、错误状态。
- 输入区：多行输入框、发送按钮、停止按钮。

建议尺寸：

- 默认宽度 420-520 px。
- 默认高度 520-680 px。
- 最小尺寸需要保证输入框和消息区可用。
- 窗口位置应靠近悬浮球展开，但不能超出屏幕边界。

### 5.3 设置页

设置页优先覆盖必要配置：

- API Key。
- Base URL。
- 模型名。
- 全局快捷键。
- 开机自启。
- 悬浮球置顶开关。默认开启。
- 清空本地数据。

API Key 输入应支持隐藏显示切换。保存后不应在主界面明文展示。

## 6. 系统架构

### 6.1 模块划分

Window Manager

- 创建悬浮球窗口和对话窗口。
- 控制窗口置顶、显示、隐藏、位置、尺寸。
- 处理拖拽和屏幕边界约束。
- 记忆悬浮球位置。

Conversation Engine

- 维护当前会话消息列表。
- 管理请求生命周期。
- 处理流式 token 增量。
- 处理停止生成。
- 管理发送中、完成、失败、中断状态。

AI Provider Adapter

- 封装 AI 服务调用。
- 输入统一消息格式。
- 输出统一流式事件。
- 第一版支持 OpenAI-compatible 接口。
- 不把具体供应商细节泄漏到 UI 层。

Settings Store

- 保存 API Key、Base URL、模型名、快捷键、开机自启、窗口位置。
- API Key 应使用系统安全存储能力或 Tauri 推荐的安全存储插件；若第一版暂用本地加密文件，必须在设置页说明“仅本机保存”。

Tray & Shortcut

- 注册系统托盘。
- 注册全局快捷键。
- 提供显示、隐藏、设置、退出入口。

UI Layer

- 渲染悬浮球。
- 渲染对话窗口。
- 渲染设置页。
- 接收用户输入并调用 Tauri commands。

### 6.2 数据流

用户发起对话：

1. 用户点击悬浮球。
2. Window Manager 显示 ChatPanel。
3. UI 聚焦输入框。
4. 用户输入问题并发送。
5. UI 将消息提交给 Conversation Engine。
6. Conversation Engine 读取 Settings Store 中的 AI 配置。
7. AI Provider Adapter 发起流式请求。
8. Conversation Engine 将流式事件推送给 UI。
9. UI 增量渲染回复。
10. 请求完成后，会话状态保存在本地。

用户停止生成：

1. 用户点击停止按钮。
2. Conversation Engine 取消当前请求。
3. AI Provider Adapter 中止网络连接。
4. UI 保留已生成内容，并标记回复已中断。

## 7. 错误处理

API Key 缺失：

- 主界面输入区可见，但发送时提示先配置 API Key。
- 提供直接进入设置页的按钮。

网络失败：

- 保留用户输入和上下文。
- 在 AI 消息位置显示错误。
- 提供重试按钮。

服务端错误：

- 显示简短错误摘要。
- 详细错误可折叠查看或复制。
- 不把用户带到浏览器网页。

流式中断：

- 保留已输出内容。
- 标记为“已停止”或“连接中断”。
- 允许重新生成。

快捷键冲突：

- 设置页提示注册失败。
- 要求用户重新绑定。

窗口越界：

- 展开对话窗口时自动贴合屏幕可见区域。
- 多显示器场景下优先使用悬浮球所在显示器。

## 8. 隐私与安全

第一版不建立自有云服务，不采集用户对话，不上传本地配置。

API Key 只保存在本机。实现时优先使用系统凭据存储或成熟安全存储插件。

应用不自动读取屏幕、剪贴板、文件或浏览器内容。只有用户主动输入的文本会发送给 AI 服务。

错误日志不得记录 API Key。若保留请求日志，只能记录时间、状态码、模型名和非敏感错误摘要。

## 9. 非功能要求

启动体验：

- 应用启动后应尽快显示悬浮球。
- 主流程不依赖打开浏览器。

资源占用：

- 空闲时 CPU 占用应接近 0。
- 空闲时不应持续轮询网络或刷新 UI。

稳定性：

- AI 请求失败不能导致应用崩溃。
- 设置损坏时应回退到默认配置并提示用户。

可维护性：

- UI 不直接拼接供应商 API 请求。
- AI Provider Adapter 和 Conversation Engine 解耦。
- 窗口管理逻辑不混入消息渲染逻辑。

## 10. 验收标准

MVP 完成时应满足：

1. 启动应用后，Windows 桌面出现置顶悬浮球。
2. 悬浮球可拖拽，重启后位置保持。
3. 点击悬浮球后，对话窗口打开且输入框自动聚焦。
4. 输入问题后，AI 回复以流式方式显示。
5. 生成过程中可以停止，已生成内容保留。
6. 回复内容可以复制。
7. 可以清空当前会话。
8. API Key、Base URL、模型名可以配置并保存。
9. API Key 缺失、网络失败、服务端错误都有明确提示。
10. 托盘菜单可以显示、隐藏、设置和退出应用。
11. 全局快捷键可以唤起或收起窗口。
12. 应用空闲时不持续占用明显 CPU。

## 11. 后续路线

第二阶段可考虑：

- 截图提问。
- 剪贴板提问。
- 选中文本快捷询问。
- 历史会话库。
- Prompt 模板。
- 语音输入。
- 本地模型接入。

这些功能必须单独设计，因为它们会引入权限、隐私、上下文来源、历史存储和更复杂的交互状态。
