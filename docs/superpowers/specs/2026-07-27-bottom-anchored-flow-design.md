# Bottom-Anchored Flow 交互设计规格

日期：2026-07-27
状态：用户已批准

## 1. 目标

将 Floating AI 从固定对话面板改为单窗口、底边锚定的连续变形交互，并彻底消除悬浮球拖动时相对鼠标的滞后。

状态流固定为：

```text
悬浮球 → 底部居中输入条 → 加载球 → 首字到达 → 回复窗口 + 底部常驻输入框
```

## 2. 架构选择

采用单原生窗口状态机。窗口标签继续使用 `floating`，React 在窗口内切换可见表面，Rust 负责原生位置、尺寸和拖动。

不采用多窗口方案：多窗口会引入焦点、置顶、DPI 和位置同步问题。不采用固定最大透明窗口：不可见区域会拦截桌面点击。

## 3. 悬浮球实时拖动

当前 JavaScript 每帧调用异步 `setPosition()` 会使 IPC 请求排队，导致窗口落后于快速移动的鼠标。

新拖动协议：

- 指针按下超过 4 px 阈值后启动一次原生拖动会话。
- Windows 原生端读取实时光标坐标并直接移动 HWND，不逐帧等待 JavaScript IPC。
- 每一帧只使用最新光标位置；旧坐标必须被覆盖而不是排队。
- 鼠标松开或取消时立即结束会话。
- 最终位置继续写入现有悬浮位置持久化设置。
- 拖动期间必须持续显示完整悬浮球，不显示系统透明矩形轮廓。
- macOS/Linux 使用同一命令契约的原生实现；若平台限制要求前端坐标，则只能允许一个位置请求在途，并以最新坐标覆盖等待值。

## 4. 输入条位置与外观

点击悬浮球后，窗口移动并变形成单输入条：

- 逻辑宽度：640 px。
- 逻辑高度：58 px。
- 水平位置：当前显示器工作区水平居中。
- 垂直位置：窗口底边距离当前显示器工作区底边 72 px。
- 必须使用工作区而非完整屏幕尺寸，避开 Windows 任务栏、macOS Dock 和 Linux 面板。
- 输入条使用现有 Graphite Terminal 黑灰材质，不使用渐变、发光、噪声或雾化。
- 仅显示真实输入面、发送、设置和收起操作，不显示空白消息页或品牌顶栏。
- 输入条空白区域可拖动窗口；交互控件不能触发窗口拖动。

## 5. 发送与加载球

发送有效内容后：

- 立即把用户消息加入会话上下文。
- 输入条从底部锚点收缩成 50×50 px 加载球。
- 加载球保持当前显示器水平居中，底边锚点不变。
- 加载动画使用灰阶旋转边框；禁止发光、渐变、闪烁和装饰粒子。
- 加载球可以停止当前生成，并提供 `aria-label` 与 tooltip。
- 加载球持续到收到首个非空流式字符。

## 6. 首字展开与流式回复

收到首个非空字符时：

- 加载球立即展开为回复窗口。
- 窗口底边保持固定，只向上增长。
- AI 内容随着现有流式 delta 逐字追加，不等待完整回复。
- 底部输入框同时恢复并常驻。
- 生成期间输入框禁用，发送按钮变为停止操作；同一时刻只允许一个请求。
- 回复完成后输入框保持可用，支持连续多轮对话。

## 7. 动态高度与滚动

回复窗口根据真实内容高度调整：

- 最小逻辑高度：120 px。
- 最大逻辑高度：560 px。
- 高度计算包含回复区、内边距、底部输入条和必要控制。
- 小于最大高度时，原生窗口随内容向上增长，消息区不显示纵向滚动条。
- 达到最大高度后，原生窗口停止增长，仅消息区启用 `overflow-y: auto`。
- 新字符到达时，如果用户此前位于消息区底部，则继续自动跟随。
- 用户主动向上滚动后，不得强制跳回底部；回到底部后恢复自动跟随。
- 代码和公式保持现有横向滚动规则，不能扩大原生窗口宽度。

## 8. 错误、停止与收起

- 首字到达前失败：加载球展开为紧凑错误条，同时恢复输入框。
- 首字到达后失败：保留已生成内容，在内容末尾显示错误状态。
- 用户在首字前停止：回到输入条，不创建空回复气泡。
- 用户在流式输出期间停止：保留已输出文字并标记“已停止”。
- `Escape` 或收起按钮将任何非设置状态恢复为悬浮球。
- 设置页继续使用现有设置表面；关闭设置后回到调用设置前的输入/回复状态，而不是强制打开旧式全高聊天面板。

## 9. 窗口动画和性能

- 所有位置与尺寸变更保持底边锚定。
- Windows 使用单次 `SetWindowPos` 同时提交位置与尺寸。
- 动态高度更新必须合并到最多每个显示帧一次，且旧高度不排队。
- 展开、收缩和内容增长采用 cubic ease-out；加载球旋转使用线性动画。
- 动画必须可被新状态打断，并继续使用 generation token 丢弃过期动画。
- 遵守 `prefers-reduced-motion: reduce`：直接切换边界，保留非运动式加载状态。

## 10. 可访问性

- 输入框、发送、停止、设置和收起操作均有中文 `aria-label`。
- 图标按钮提供 tooltip。
- 流式回复区使用 `aria-live="polite"`，但避免每个字符触发完整内容重复朗读。
- 加载球提供可读状态“正在等待 AI 回复”。
- 键盘焦点在输入条展开后进入输入框；回复完成后不抢夺用户当前焦点。

## 11. 验收标准

1. 快速拖动悬浮球时，球体与鼠标保持同步，不出现可观察的持续滞后。
2. 拖动期间显示完整球体，不显示透明矩形轮廓。
3. 点击球后只显示宽 640 px、高 58 px 的底部居中输入条。
4. 输入条底边距当前显示器工作区底部 72 px。
5. 发送后输入条变成 50×50 px 灰阶加载球。
6. 首个非空流式字符到达后立即展开回复窗口并逐字输出。
7. 回复窗口只向上增长，高度限制在 120–560 px。
8. 超过最大高度时，仅消息区出现纵向滚动条。
9. 回复区和底部输入框在首字到达后同时常驻，可连续多轮提问。
10. 用户向上阅读时不会被新字符强制拉回底部。
11. 首字前错误、流式错误、首字前停止和流式停止均符合第 8 节。
12. 原有 Markdown、代码高亮、复制、LaTeX、设置、快捷键、托盘和自动启动功能保持可用。
