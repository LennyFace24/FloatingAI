# Draggable Bounded Surfaces 设计规格

日期：2026-07-27
状态：用户已批准

## 目标

除悬浮球外，输入条、等待球、回复窗口和设置页均可自由拖动。程序打开设置页时确保窗口完整位于当前显示器工作区内；用户随后主动拖出工作区时不自动纠正。

## 拖动行为

- 所有拖动统一使用现有原生窗口拖动命令，避免 Windows 系统透明轮廓和 JavaScript 位置请求积压。
- 指针移动达到 4 px 后启动拖动；未达到阈值仍按正常点击处理。
- 回复页和设置页从顶栏非交互区域拖动。
- 输入条从输入容器的非交互空白区域拖动；textarea、发送、设置和收起控件保持正常交互。
- 等待球使用点击/拖动判定：单击停止生成，移动达到阈值则拖动窗口且不触发停止。
- 消息滚动区、输入框、表单字段、复选框和按钮不能触发窗口拖动。
- 用户拖动结束后继续使用现有 debounce 保存最终浮球位置；非浮球页面位置不作为新的默认锚点。

## 程序打开设置页的位置约束

设置页目标逻辑尺寸为 460×560 px。打开设置页时：

1. 读取当前窗口所在显示器的工作区和缩放比例。
2. 将目标尺寸转换为物理像素。
3. 若目标尺寸超过工作区，先分别缩小到工作区宽高。
4. 保留当前窗口左上角位置，但夹紧到完整可见范围：

```text
x = clamp(current_x, work_left, work_right - target_width)
y = clamp(current_y, work_top, work_bottom - target_height)
```

5. 使用一次原生 bounds 提交同时设置位置和尺寸，然后显示并聚焦设置页。

该约束只在程序打开设置页时执行。窗口显示后，用户可以主动拖到工作区之外，移动事件不得自动夹紧。

## 状态与兼容性

- 打开设置页前取消正在进行的窗口边界动画。
- 设置页边界提交成功后才发布 Settings 窗口模式。
- 设置页关闭后仍由现有 assistant phase 恢复输入、等待或回复窗口。
- 多显示器和负坐标显示器必须使用当前显示器工作区原点计算。
- 回复、输入和等待状态的程序化打开继续使用既有底部居中规则。

## 可访问性

- 可点击的拖动表面继续提供原有 aria-label 和 tooltip。
- 等待球单击停止、拖动移动，两种行为必须互斥。
- 键盘输入、文本选择、消息滚动和表单操作不受拖动处理影响。

## 验收标准

1. 输入条、等待球、回复页和设置页均可拖动。
2. 拖动过程中显示完整窗口内容，不显示透明矩形轮廓。
3. 等待球单击停止，拖动时不停止。
4. 输入框可选择文本；按钮、表单和消息滚动不误触拖动。
5. 从屏幕底部输入条打开设置页时，设置页完整位于当前显示器工作区内。
6. 设置页在负坐标副屏和缩放显示器上仍完整可见。
7. 用户主动将设置页拖出屏幕后，应用不自动拉回。
8. 设置页关闭后恢复此前 assistant phase。
